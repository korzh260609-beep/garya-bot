---

## 1. Назначение проекта

SG 2.0 / Советник GARYA — это глобальная проектная система Советника для помощи людям в:

- мышлении;
- анализе;
- памяти;
- ведении проектов;
- работе с источниками;
- создании документов и решений;
- управлении задачами;
- безопасном выполнении разрешённых действий.

SG не является просто чат-ботом, набором команд, одним агентом, одним интерфейсом или только Task Engine.

---

## 2. Базовая идея

SG помогает пользователю:

- структурировать хаос;
- видеть риски;
- проверять логику;
- помнить решения;
- опираться на источники;
- превращать свободные запросы в понятные действия, планы, отчёты или проверки.

Принцип:

```text
SG не подменяет человека.
SG не принимает финальные решения за пользователя.
SG не действует самовольно.
SG свободен в мышлении и управляем в действиях.
```

---

## 3. Королевство GARYA

SG создаётся внутри концепции Королевства GARYA.

Королевство задаёт:

- философию;
- роль монарха;
- правила управления;
- ответственность;
- долгосрочное направление развития.

SG является центральным цифровым механизмом Королевства, но не субъектом власти.

Принцип:

```text
Королевство задаёт волю и правила.
SG помогает исполнять их корректно и последовательно.
```

---

## 4. Архитектурная модель

SG 2.0 строится как слоистая модульная система:

```text
Transport Layer
-> Core / Orchestrator
-> Permissions / Capabilities
-> Memory & Context
-> Sources Layer
-> AI Layer
-> Delivery / Actions
```

Transport может быть Telegram, web, API, IDE или другой канал.
Transport не должен становиться ядром SG.

---

## 5. Ключевой flow

Главная рабочая формула:

```text
Meaning -> Intent -> Context -> Capability -> Permission -> Source/Tool -> Processing -> Result/Action -> Delivery
```

СГ сначала понимает смысл, затем выбирает capability, проверяет права и источники, и только потом отвечает или выполняет разрешённое действие.

---

## 6. Source-first

SG работает по принципу source-first.

ИИ не является источником истины.

Если нужны факты, SG должен опираться на:

- repository/runtime;
- API;
- RSS;
- web;
- документы;
- базы данных;
- пользовательские источники;
- сохранённую память.

---

## 7. Memory-first, но не memory-only

SG должен иметь долговременную память, но память не заменяет источники и не заменяет pillars.

Память используется для:

- контекста;
- преемственности;
- проектного опыта;
- предпочтений;
- решений;
- истории задач.

Pillars остаются канонической правдой проекта.

---

## 8. Экономия ресурсов

SG должен различать:

- робот-слой — дешёвые проверки, правила, источники, расписания;
- ИИ-слой — смысл, анализ, выводы и сложные формулировки.

ИИ-слой используется тогда, когда он действительно нужен.

---

## 9. Multi-user ready

SG 2.0 проектируется как мультиюзерная система.

Каждый пользователь должен иметь изолированные:

- память;
- проекты;
- источники;
- настройки;
- роли;
- лимиты;
- историю задач.

Проект `garya-bot` является проектом монарха и не должен автоматически становиться default-контекстом обычных пользователей.

## 11. Canonical reminder

SG 2.0 — это долгоживущая проектная система Советника.

Она должна быть:

- meaning-first;
- source-first;
- modular;
- multi-user ready;
- memory-aware;
- controlled by permissions;
- governed by Monarch decisions;
- extensible without breaking the core.
