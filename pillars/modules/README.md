# pillars/modules — SG 2.0 Module Docs

> AGENT NOTE:
> This folder contains module-level documentation for SG 2.0.
> Read `MODULE_INDEX.md` first, then the relevant module README.
> Do not create module docs as random notes, duplicate global architecture, or treat any module as SG itself without explicit Monarch approval.

Статус: ACTIVE SKELETON

---

## Purpose

This folder defines boundaries for SG 2.0 modules before implementation grows.

Module docs must answer:

- why the module exists;
- what it owns;
- what it must not own;
- what it connects to;
- what risks it creates;
- what permissions/confirmations it needs.

---

## Current rule

At this stage modules are documented as skeletons only.

Full module docs like `CONTRACTS.md`, `RISKS.md`, and `CHANGELOG.md` should be added when a module becomes active enough to need them.

---

## Reading order

1. `pillars/modules/MODULE_INDEX.md`
2. target module `README.md`
3. relevant architecture docs
4. active workflow block
